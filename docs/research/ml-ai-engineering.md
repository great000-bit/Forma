**How this differs.** ML engineers are judged on systems that run: architecture, latency, cost, evaluation and deployment. LLM/RAG work in 2026 needs evals and failure analysis, not just a demo.

## Patterns

- Case studies read like engineering reports: role, stack, context, outcome first.
- Architecture diagrams, eval tables (metric, baseline, result), latency/cost numbers.
- Live demos (Gradio, Streamlit, Hugging Face Spaces) and repos.
- Writing and teaching build authority (long-form posts, courses).
- Confidential production work rebuilt as a public demo.

## Required sections for the interview agent (ML/AI Engineering)

1. Identity: name, title, level, city, remote.
2. Focus: LLM apps/RAG/agents, CV, NLP, recsys, MLOps, research.
3. Projects (3 to 5): problem, architecture, data, model choice and why, evaluation (metrics vs baseline), deployment (where, scale), result, links (repo, demo, paper).
4. Stack: PyTorch, TensorFlow, JAX, Hugging Face, LangChain/LlamaIndex, vector DBs, cloud, Docker/K8s.
5. Papers, open source, talks, writing (optional).
6. Experience and education.
7. Contact: email, WhatsApp, LinkedIn, GitHub, Hugging Face, Google Scholar.
