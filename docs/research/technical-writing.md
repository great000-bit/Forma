## Patterns

- Samples grouped by doc type: API reference, tutorial, how-to, conceptual, user guide, release notes, UI copy.
- Each sample states audience, goal, tools (Markdown, Git, Docusaurus, MkDocs, OpenAPI, DITA, MadCap Flare), and the writer's role.
- Before/after rewrites show editing skill.
- Docs-as-code: link to repo PRs and live docs.
- Services and pricing for freelancers.

## Required sections for the interview agent (Technical Writing)

1. Identity: name, title (technical writer, API writer, developer educator, docs engineer), city, remote.
2. Doc types you write and audiences (developers, end users, admins).
3. Samples (3 to 6): title, type, audience, problem, your role, tools, link or PDF, optional before/after excerpt.
4. Tools and stack; languages you can read (Python, JS, SQL).
5. Experience, clients.
6. Testimonials (optional).
7. Contact: email, WhatsApp, LinkedIn, GitHub.
